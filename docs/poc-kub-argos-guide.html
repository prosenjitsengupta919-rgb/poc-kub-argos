1. End Goal

The final system should automatically test pull requests in isolated Kubernetes environments.

PR opened or updated
Create namespace such as test-pr-25
Deploy the PR version of the app into that namespace
Run Playwright visual tests against the deployed app
Upload screenshots and visual comparison results to Argos
Report pass or fail back to the PR
Delete the temporary namespace

The current POC proves the pieces manually first. Later, hardcoded values like main, test-pr-1, and poc-kub-argos:latest will become PR-driven parameters.

2. Architecture

Tool Role In This POC
Kubernetes Runs the application pod, service, test namespace, and workflow pods.
Docker Builds the app image poc-kub-argos:latest.
Playwright Opens the app and captures visual screenshots.
Argos Stores visual test screenshots and compares builds.
Argo CD Watches Git and keeps stable Kubernetes app manifests synced.
Argo Workflows Runs the temporary PR-style pipeline: deploy, test, cleanup.
CronWorkflow Runs the workflow on a schedule.

4. Step 2: Add TestPackage YAML

The TestPackage YAML is a small instruction file. It is like a test order form. It says which app to deploy, which image to use, where the tests live, and what command should run them.

File:

test-packages/demo/next-ui.yaml
apiVersion: testinfra.poc/v1alpha1
kind: TestPackage
metadata:
  name: next-ui-visual
  owner: demo
spec:
  trigger:
    - onPullRequest
  target:
    app:
      name: poc-kub-argos
      image: poc-kub-argos:latest
      servicePort: 80
      containerPort: 3000
  source:
    repo: https://github.com/prosenjitsengupta919-rgb/poc-kub-argos.git
    ref: main
    path: .
  runner:
    type: playwright
    image: mcr.microsoft.com/playwright:v1.61.0-noble
    command: npm run test:visual:ci
  notifications:
    argos: true

Field Explanation

Field Meaning
apiVersion Version of this custom POC contract.
kind Declares this document as a TestPackage.
metadata.name Name of this test package.
metadata.owner Owner label used in generated Kubernetes manifests.
spec.trigger Future intent: run when a pull request event happens.
spec.target.app.name Kubernetes app, deployment, and service name.
spec.target.app.image Docker image Kubernetes should run.
servicePort Port exposed by the Kubernetes Service.
containerPort Port where the app listens inside the container.
source.repo Git repository containing the app and tests.
source.ref Git branch or commit to clone. Currently main.
source.path Folder inside the repo where commands should run.
runner.type Test runner type. Current value is playwright.
runner.image Container image used to run the tests in Kubernetes.
runner.command Command that starts the test.
notifications.argos Signals that visual results should be sent to Argos.

5. Step 3: Add Render Script

The render script is the translator. It reads the TestPackage YAML and generates Kubernetes YAML files.

Script:

scripts/render-test-package.mjs

Run:

npm run render:test-package
Part Meaning
npm Node package manager.
run Runs a script from package.json.
render:test-package Script alias that runs node scripts/render-test-package.mjs.

Expected output:

Rendered test-packages/demo/next-ui.yaml into rendered/test-pr-1
Apply with: kubectl apply -f rendered/test-pr-1

Generated files:

rendered/test-pr-1/namespace.yaml
rendered/test-pr-1/deployment.yaml
rendered/test-pr-1/service.yaml
rendered/test-pr-1/job.yaml

Generated File Meaning

File Meaning
namespace.yaml Creates the temporary isolated test namespace.
deployment.yaml Runs the app pod in Kubernetes.
service.yaml Gives the app a stable internal network address.
job.yaml Describes a test runner job that can clone the repo and run Playwright.

Custom Namespace Render

npm run render:test-package -- test-packages/demo/next-ui.yaml test-pr-123
Part Meaning
-- Separates npm arguments from script arguments.
test-packages/demo/next-ui.yaml Input TestPackage file.
test-pr-123 Output namespace name.

7. Step 5: Run Visual Test Against Deployed App

The important idea is that Playwright should test the app deployed in Kubernetes, not the local Next.js dev server.

Headless Scripted Mode

npm run test:deployed

This opens a temporary port-forward to the Kubernetes Service and runs the visual test with PLAYWRIGHT_BASE_URL pointing at that port-forward.

Headed Mode With Browser Visible

Use two terminals.

Terminal 1

kubectl -n test-pr-1 port-forward service/poc-kub-argos 31080:80
Part Meaning
-n test-pr-1 Use the temporary test namespace.
port-forward Forward local traffic into Kubernetes.
service/poc-kub-argos Forward to the Kubernetes Service named poc-kub-argos.
31080:80 Local port 31080 forwards to Service port 80.

Terminal 2

PLAYWRIGHT_BASE_URL=http://127.0.0.1:31080 npm run test:visual
Part Meaning
PLAYWRIGHT_BASE_URL=... Tells Playwright to test the deployed app URL.
npm run test:visual Runs Playwright in headed mode.

9. Step 7: Argo CD

Argo CD is GitOps. It watches a Git repository and keeps Kubernetes synced with what is in Git.

Important: Argo CD is best for stable environments like dev, staging, and production. Argo Workflows is better for temporary PR test namespaces.

Install Argo CD

kubectl create namespace argocd
Part Meaning
create namespace Create an isolated Kubernetes namespace.
argocd Name of the namespace where Argo CD will run. 
kubectl apply -n argocd -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml
Part Meaning
apply Create or update resources from YAML.
-n argocd Install into the argocd namespace.
-f URL Read the install YAML from the official Argo CD GitHub URL.

Wait For Pods

kubectl -n argocd get pods -w

The -w flag watches live changes. Wait until argocd-server is 1/1 Running.

Open Argo CD UI

kubectl -n argocd port-forward svc/argocd-server 8080:443

Open:

https://localhost:8080

Username:

admin

Get password:

kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath='{.data.password}' | base64 -d; echo

Create Application From UI

UI Field Value

Enable these options for the POC:

10. Step 8: Argo Workflows

Argo Workflows runs the test pipeline. It can create a namespace, deploy the app, run Playwright, upload to Argos, and clean up.

Install Argo Workflows

kubectl create namespace argo
kubectl apply --server-side -n argo -f https://github.com/argoproj/argo-workflows/releases/latest/download/install.yaml
If normal kubectl apply fails with annotation size errors, use --server-side. If it reports conflicts, use --server-side --force-conflicts.

Wait For Pods

kubectl -n argo get pods -w

Wait for:

  • argo-server as 1/1 Running
  • workflow-controller as 1/1 Running

Open Argo Workflows UI

kubectl -n argo port-forward deployment/argo-server 2746:2746

Open:

https://localhost:2746

If port 2746 is already used, use another local port:

kubectl -n argo port-forward deployment/argo-server 2747:2746

Then open:

https://localhost:2747

Create Workflow Runner Permissions

kubectl create serviceaccount argo-workflow-runner -n argo --dry-run=client -o yaml | kubectl apply -f -
Part Meaning
serviceaccount Identity used by workflow pods.
argo-workflow-runner Name of the workflow service account.
--dry-run=client -o yaml Print YAML instead of immediately creating it.
| kubectl apply -f - Apply the generated YAML from standard input. 
kubectl create clusterrolebinding argo-workflow-runner-admin \
  --clusterrole=cluster-admin \
  --serviceaccount=argo:argo-workflow-runner \
  --dry-run=client -o yaml | kubectl apply -f -
POC only: cluster-admin is broad. It is convenient for local learning. A real system should use narrower RBAC.

Run One Workflow

kubectl create -f argo-workflows/poc-kub-argos-workflow.yaml
Part Meaning
create Create a new resource. Needed because the Workflow uses generateName.
-f Read resource YAML from a file.
argo-workflows/poc-kub-argos-workflow.yaml The one-time Workflow manifest.
Use kubectl create, not kubectl apply, for this file because it uses metadata.generateName.

Watch Workflow

kubectl -n argo get workflows
kubectl -n argo get pods

Get logs from the Playwright pod:

kubectl -n argo logs <playwright-pod-name> -c main

11. CronWorkflow

A Workflow runs once. A CronWorkflow runs a Workflow repeatedly on a schedule.

File:

argo-workflows/poc-kub-argos-cronworkflow.yaml

Apply CronWorkflow

kubectl apply -f argo-workflows/poc-kub-argos-cronworkflow.yaml

Check:

kubectl -n argo get cronworkflows

Important Fields

Field Meaning
schedules List of cron schedules. Current value runs every 15 minutes.
timezone Schedule timezone. Current value is Asia/Kolkata.
suspend If true, the schedule is paused.
concurrencyPolicy: Forbid Do not start a new run if the previous one is still running.
successfulJobsHistoryLimit How many successful workflow histories to keep.
failedJobsHistoryLimit How many failed workflow histories to keep.

Start Schedule

kubectl -n argo patch cronworkflow poc-kub-argos-scheduled --type=merge -p '{"spec":{"suspend":false}}'
Part Meaning
patch Change part of an existing Kubernetes resource.
cronworkflow The resource type being patched.
poc-kub-argos-scheduled Name of the CronWorkflow.
--type=merge Use merge patch style.
-p '{"spec":{"suspend":false}}' Patch body that turns the schedule on.

Pause Schedule

kubectl -n argo patch cronworkflow poc-kub-argos-scheduled --type=merge -p '{"spec":{"suspend":true}}'

12. Argos Token And Results

The Playwright config uploads to Argos when both conditions are true:

  • CI=true
  • ARGOS_TOKEN exists

Create Secret

kubectl -n argo create secret generic argos-token --from-literal=ARGOS_TOKEN='<your-argos-token>'
Part Meaning
-n argo Create the secret in the namespace where Workflow pods run.
create secret generic Create a simple key-value Kubernetes secret.
argos-token Name of the secret referenced by workflow YAML.
--from-literal=ARGOS_TOKEN=... Create a secret key named ARGOS_TOKEN with your token value.

Verify Secret Exists

kubectl -n argo get secret argos-token

Verify Pod Receives Secret

kubectl -n argo get pod <playwright-pod-name> -o yaml | grep -A8 ARGOS_TOKEN

Expected shape:

- name: ARGOS_TOKEN
  valueFrom:
    secretKeyRef:
      key: ARGOS_TOKEN
      name: argos-token

Successful Argos Log

✅ Argos build created: https://app.argos-ci.com/prosenjitsengupta919/poc-kub-argos/builds/6

This confirms visual screenshots were uploaded. Open the URL to see Argos results.

13. Troubleshooting

Argo CD Pod Pending

kubectl -n argocd get pods -w

If pods are ContainerCreating or PodInitializing, wait. First image pulls can take minutes.

Namespace Not Found In Argo CD

kubectl create namespace poc-kub-argos

This fixes namespaces "poc-kub-argos" not found if auto-create namespace was not enabled.

Port Already In Use

Unable to listen on port 2746: bind: address already in use

This means another port-forward is already running. Either stop it with Ctrl + C or use a different local port: 

kubectl -n argo port-forward deployment/argo-server 2747:2746

HTTP Sent To HTTPS Server

Client sent an HTTP request to an HTTPS server.

Use:

https://localhost:2746

Workflow Pod Pending

kubectl -n argo describe pod <pod-name>

Check the Events section. For the Playwright image, the first pull can be close to 1 GB and may take several minutes.

Argos Token Present But No Upload

Check that the pod has both:

  • ARGOS_TOKEN
  • CI=true
kubectl -n argo get pod <playwright-pod-name> -o yaml | grep -A12 ARGOS_TOKEN

Workflow Uses Old Code

The workflow currently clones GitHub main. Local changes are not seen by workflow pods until they are committed and pushed, or until the workflow is changed to clone another branch/ref.
